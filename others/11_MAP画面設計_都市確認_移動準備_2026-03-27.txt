--------------------------------------------------
0. この仕様書の目的
--------------------------------------------------
本仕様書は、MAP画面における「都市を確認する操作」と「移動準備を行う操作」を、
ひとつの画面の中でどう繋ぐかを定義する。

これまで護衛UIを独立した窓として扱う方向も検討していたが、
現在の方針では護衛は独立UIの主役ではなく、移動準備の一部として扱う。

本仕様書は、
- MAPを単なる背景ではなく判断材料として活かすこと
- ルート選択 / コスト / 危険 / 護衛をひとまとまりの移動準備として扱うこと
- 既存の HUD / WINDOW / DIALOG / MAP の責務分担を崩さないこと
を目的とする。

--------------------------------------------------
1. 今回の再定義
--------------------------------------------------
これ以降の検討対象は「護衛UIをどう出すか」ではなく、
「MAP画面の中で、都市確認から移動準備までをどう繋ぐか」である。

護衛は独立ウィンドウの主役ではなく、移動準備の一部として扱う。
これは、もともとの移動仕様が「ルート選択 / コスト配分 / 護衛」をひとまとまりで完成させる前提だったこととも整合する。

要するに、今回の論点は護衛単体ではなく、MAP画面の状態遷移設計である。

--------------------------------------------------
2. 基本方針
--------------------------------------------------
2.1 MAP画面は分離しない
- 「都市情報確認用MAP」と「都市間移動用MAP」は別画面に分離しない。
- 同じMAP画面を使い、内部状態のみを切り替える。

理由:
- MAPは単なる背景ではなく、ルート判断そのものの材料だから。
- 目的地クリックから最大3候補の比較へ進む既存の移動仕様と整合するから。
- HUD主導で MAP / WINDOW / DIALOG の責務を分ける既存整理と相性がよいから。

2.2 MAP画面の役割
MAP画面は、単に目的地を選ぶだけの場所ではない。
都市の位置関係、経路、危険、経由地、距離感を読み取り、
「どのように向かうか」を考えるための中核画面として扱う。

--------------------------------------------------
3. MAP画面の内部状態
--------------------------------------------------
MAP画面は少なくとも以下の3状態で運用する。

3.1 MAP_BROWSE
- 地図を見る基本状態
- 都市一覧、通常のパン/ズーム、全体把握が主目的
- 都市ノード未選択の通常閲覧状態

3.2 MAP_CITY_FOCUS
- 都市ノードを選択した状態
- その都市の情報確認が主目的
- 左側に都市情報パネルを表示する
- 右側には都市一覧が残っていてよい

3.3 MAP_TRAVEL_PREP
- 移動準備を行う状態
- ルート、日数、総費用、危険度、護衛を確認し、出発可否を決める段階
- 左側の都市情報パネルを、移動準備パネルに置き換える
- 中央のMAPは残し、むしろルート判断の主役として強調する

3.4 状態遷移の基本導線
MAP画面内では、以下の流れで遷移させる。

MAP_BROWSE
  → 都市ノード選択
MAP_CITY_FOCUS
  → 「移動」選択
MAP_TRAVEL_PREP
  → 出発 または 戻る

この導線により、同じMAP画面の中で
「閲覧 → 都市確認 → 移動準備」
が滑らかに繋がる構成にする。

--------------------------------------------------
4. 都市ノード選択時の見せ方
--------------------------------------------------
4.1 フォーカス位置
都市ノードを選択したら、その都市が見やすい位置へフォーカス移動する。
ただし、厳密に画面中央へ固定する必要はない。
左パネルや右側一覧の存在を考慮し、実際に視認しやすい位置へ寄せる前提でよい。

4.2 左パネル
MAP_CITY_FOCUS では、左側に都市情報パネルを表示する。
ここでの主役は「都市そのものを知ること」であり、まだ移動準備画面ではない。

想定される内容例:
- 都市名
- 所属プロヴィンス
- 概要メモ
- 主な取引/産業の手掛かり
- 現在地から見た位置づけ
- 移動ボタン

4.3 右側一覧
右側には既存想定どおり都市一覧が残っていてよい。
一覧はMAPの補助UIとして扱い、都市選択導線を担う。

--------------------------------------------------
5. MAP_TRAVEL_PREP の基本設計
--------------------------------------------------
5.1 中央モーダル化しない
MAP_TRAVEL_PREP は中央の大きな確認ダイアログとして実装しない。
左の都市情報パネルを、移動準備パネルへ置き換える方式を採用する。

理由:
1. 中央ダイアログ方式は要素が重なりやすく、視認性と入力制御が崩れやすい。
2. 移動準備は単なる Yes / No 確認ではなく、比較と判断の画面だから。
3. 地図を見ながら考えること自体が、この作品の面白さと直結しているから。

5.2 MAPは消さない
MAP_TRAVEL_PREP に入っても中央のMAPは消さない。
むしろ、現在地からどう向かうのかが分かりやすいように、
引き気味で表示し、ルート可視化を主役にする。

5.3 判断の中心
この状態では、左パネルが主役ではなく、ルートを読む地図が主役である。
左パネルは判断材料を整理する補助UIとして働く。

--------------------------------------------------
6. MAP_TRAVEL_PREP で地図上に見せるべき情報
--------------------------------------------------
MAP_TRAVEL_PREP では、少なくとも以下が視認しやすい必要がある。

- 現在地
- 目的地
- 選択中ルート
- 将来の別候補ルート
- 経由都市
- 危険の目安

この可視化は、将来の「最短 / 最安 / 最安全」比較のための土台でもある。
また、世界観上も、陸路再構築と物流の詰まりを読む体験に直結する。

--------------------------------------------------
7. 護衛の位置づけ
--------------------------------------------------
7.1 護衛は独立UIの主役ではない
左都市情報パネルの「移動」から入る先は、護衛ウィンドウではなく移動準備パネルである。
その中に護衛選択の要素を含める。

7.2 護衛の役割
護衛は、
- 独立ポップアップの主役ではない
- 移動確認の一部である
- ルート / 費用 / 危険度 と並んで判断される要素である
という位置づけで扱う。

7.3 方針上の意味
これは、護衛を独立ゲーム化しないという方針、
および「移動前判断を少し豊かにする補助システム」という整理に一致する。

--------------------------------------------------
8. MAP_TRAVEL_PREP 左パネルの役割
--------------------------------------------------
左パネルに載せる主要情報は、現時点では以下を基本とする。

- 出発地 → 目的地
- ルート種別
- 日数
- 総費用
- 危険度の目安
- 護衛編成サマリ
- 出発
- 戻る

補足:
- 護衛候補の詳細一覧を常時フル表示する必要は、まだない。
- 将来的に情報量が増えることを考えると、同じ左パネル内で切替表示できる構成の方が伸びしろがある。
- ただし、少なくとも「護衛を中央別窓で重ねる」方向には戻らない。

--------------------------------------------------
9. 入力制御と責務整理
--------------------------------------------------
今回見えてきた問題は、個別パッチ不足というより、状態設計の不足である。

そのため、今後は以下のように整理する。

- DIALOG:
  最優先のモーダル。会話やシステム通知の表示を担う。

- WINDOW:
  市場、在庫、共通ウィンドウ群。HUD主導で管理する。

- MAP_TRAVEL_PREP:
  MAP画面内の状態遷移。別モーダルの追加ではなく、MAP内部状態として扱う。

この整理により、
「移動準備を別モーダルで解決しようとして入力制御が複雑化する」流れを避ける。

--------------------------------------------------
10. 既存方針との整合
--------------------------------------------------
10.1 憲法との整合
本方針は、以下の憲法上の主役を強める。
- プレイヤー自身の移動
- 契約に向けた旅の判断
- 地理的制約や物流の不便さを読む面白さ

つまり、MAP_TRAVEL_PREP で地図を消さず、
ルート可視化を主役にする判断は、本作の中心体験と一致する。

10.2 移動仕様との整合
既存の「最短 / 最安 / 最安全」の最大3候補比較、
およびルート選択を中核に据える考え方と整合する。

10.3 会話UI/モーダル設計との整合
会話やシステム表示のモーダル性と、
MAP内部状態の遷移を分離できるため、責務が明確になる。

--------------------------------------------------
11. 現時点での保留事項
--------------------------------------------------
骨格は確定している。
ただし、実装前に以下3点を軽く決めるとよりスムーズである。

A. MAP_TRAVEL_PREP 中の地図操作範囲
- 自動フレーミングのみとするか
- ある程度の手動パン/ズームを許すか

B. ルートの視覚表現
- 選択中ルート
- 非選択候補
- 危険区間
- 経由都市
をどこまで常時表示するか

C. 左パネルの情報量
- 護衛候補詳細を常時表示するか
- 編成サマリ中心にして詳細は切替にするか

これらは微調整項目であり、本仕様の骨格を止める未決事項ではない。

--------------------------------------------------
12. 現時点の一文要約
--------------------------------------------------
護衛システムは独立UIではなく、MAP画面内の MAP_TRAVEL_PREP 状態に統合し、
左パネルで準備情報を扱いながら、中央には引きのMAPとルート可視化を残す。

--------------------------------------------------
13. 実装に向けた短い補足
--------------------------------------------------
実装責務の大枠は以下を推奨する。

- game_hud.gd:
  MAP画面状態の管理、左パネル差し替え、入力制御の統括

- map_layer.gd:
  都市フォーカス、ルート可視化、フレーミング、地図操作

- world.gd:
  ルート候補、日数、費用、危険度、護衛適用後の計算など状態計算

この仕様書はUI構成と責務整理の資料であり、
数値計算や具体的なルート比較アルゴリズムの詳細は別途移動仕様側で扱う。

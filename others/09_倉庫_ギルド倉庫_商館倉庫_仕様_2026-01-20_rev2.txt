倉庫（ギルド倉庫／商館倉庫） 仕様 2026-01-20 rev2

0) 目的（この仕様で解決したいこと）
- 序盤から「積み替え（短期保管）」の選択肢を与え、積載・税・移動日数の最適化に“段取り”の楽しさを足す。
- ただし、行商（自分で運ぶ）と道中イベント（1日単位）を主役のまま維持する。
- 中盤以降の商館（支店）＝自前倉庫の価値を守り、上位互換にしない（ギルド倉庫は弱い・限定的）。

1) 用語
- ギルド倉庫（公設倉庫 / Public Depot）
  各プロヴィンスに原則1拠点。商人ギルド運営。序盤から利用可能（ただし州外は利用権が必要）。
- 商館倉庫（Branch Warehouse）
  プレイヤーの商館（支店）に付随する倉庫。将来、設備で食品なども扱えるように拡張する。
- 利用権（Permit）
  プロヴィンス単位の倉庫利用許可。倉庫拠点が増えても同一許可で利用できる。

2) 倉庫の種類と差別化
2.1 ギルド倉庫（公設）
- 運営: 商人ギルド（都市の自治・領主と協定を結んだ“公認”施設）
- 役割: 積み替え・短期保管（旅の段取り支援）
- 強み: 序盤から使える／プロヴィンス単位で利用権を取れば複数拠点にも拡張可能
- 弱み（商館倉庫との差別化）
  - 収容容量が小さい
  - 保管料がかかる
  - 食品・酒類など“傷みやすい/嗜好品”は原則不可（または厳しい制限）
  - “遠隔引き出し”は不可（同じ倉庫拠点に行かないと出せない）

2.2 商館倉庫（支店付属）
- 運営: プレイヤー（支店の雇人・番人）
- 役割: 契約・委託・情報収集の準備拠点として長期保管も視野
- 差別化:
  - 収容容量が大きい
  - 仕入れ・納品の準備に向く（契約システムと接続しやすい）
  - 食品は設備アップグレードで解禁（乾物庫/塩蔵庫/冷蔵など）
  - 維持費（家賃・人件費）でコストを表現

2.3 ギルド“出張所”（任意・将来）
- 倉庫を置かず、手続き（利用権申請・通行手形・情報）だけ提供する施設。
- 例: 倉庫を置いた都市がハブ化しすぎる場合、倉庫ではなく出張所にして価値を分散できる。

3) 初期配置（現状の決定）
- Pilton: RE0002 Boroughambe（cities.note=倉庫）
- Stormcape: RE0016 Node16（cities.note=倉庫）
- East-havn: RE0012 Node12（cities.note=倉庫）

補足
- cities.csv の note 列「倉庫」を“倉庫の存在”判定（UI表示・利用可否）に利用する。
- 将来、倉庫種別（ギルド/支店/出張所）を増やす場合は warehouses.csv 等の別CSVを追加して拡張する。

4) 利用条件（プロヴィンス利用権）
4.1 基本
- 倉庫の利用可否は「現在地のプロヴィンスの利用権」で判定する。
- 倉庫拠点が複数になっても、許可はプロヴィンス単位で共有する（“まとめる”方針）。

4.2 解禁フロー（推奨：信用で解禁）
- Pilton: 初期から利用可（チュートリアル導線に使用できる）
- 他プロヴィンス: rep_by_province[province] が閾値以上で解禁
  - 閾値例（調整枠）
    - East-havn: 10
    - Stormcape: 15
  - さらに雰囲気を出すなら「申請手数料（1回）」を追加

4.3 失効（当面なし）
- MVPでは失効なし。
- 将来、犯罪・密輸・未払いで“停止”を入れる余地はある。

5) 取り扱い制限（食品・酒類など）
5.1 基本ルール（ギルド倉庫）
- ギルド倉庫は原則として以下を預けられない（MVPの制約）
  - category が food / drink の商品
  - もしくは decay_rate > 0 の商品（将来の腐敗実装に合わせる）

5.2 商館倉庫
- 初期はギルド倉庫と同様の制限でもよい。
- 設備アップグレードで食品を段階的に解禁する。

6) 料金（ギルド倉庫）
6.1 方針
- “積み替えは便利だが無料ではない”を明確にする。
- ただし旅の主役（移動・イベント）を邪魔しない程度の薄いコストに留める。

6.2 料金体系（推奨）
- 入庫手数料: in_fee = 0.1G + 0.01G * 入庫ユニット数
- 出庫手数料: out_fee = 0.1G + 0.01G * 出庫ユニット数
- 保管料（日次）: store_fee = 0.02G * 保管中の総容量（carry_size換算）
  - 最低 0.2G/日（何か預けているなら）

補足
- “ユニット数”は qty のこと。容量（carry_size）は products.csv の carry_size を参照する。
- 数値はバランス調整枠（体験版で上下させる前提）。

6.3 支払いタイミング
- 入出庫手数料: 操作実行時に即時
- 保管料（日次）: 日次更新（day advance）時に引き落とし
  - 所持金不足時は、MVPでは「保管料だけ踏み倒し」を許さず、以下のどちらか
    A) 取り立て（負債）として記録して以後の利用を停止
    B) 倉庫の一部差し押さえ（価値の低いものから）
  - 実装が軽いのは A（負債＋停止）。

7) 容量（キャパシティ）
7.1 ギルド倉庫
- プロヴィンス1拠点運用を前提に、控えめ（例: 30容量）
- 都市Rankで微差をつける余地はあるが、MVPは固定でもよい

7.2 商館倉庫
- 支店段階に応じて増える（例: 60/90/120）
- 維持費や建設条件で抑制する

8) 禁止事項（悪用防止）
- 倉庫間の自動転送（遠隔配送）はしない
  - 「預けた都市に取りに行く」ことが旅の設計に効く
- 同一日に“無限入出庫”で手数料ゼロになる抜け道は作らない
  - 手数料は操作ごとに必ず発生（最低料金あり）

9) UI: 倉庫専用ウィンドウ（最終形の要件）
9.1 入口（開き方）
- 都市画面で「倉庫」コマンドが表示される条件
  - 現在地の都市に倉庫がある（cities.note に「倉庫」）
  - かつ、そのプロヴィンスの利用権を持っている

9.2 レイアウト（最終形）
- 左: プレイヤー所持（Inventory / Cargo）
- 右: 倉庫（Warehouse）
- 上部に情報
  - 現在地 / 倉庫名（ギルド倉庫）
  - 容量バー（使用量/最大）
  - 手数料・日次保管料の説明（短文）

9.3 ドラッグ＆ドロップ操作（最終形）
- Inventory → Warehouse にドロップ: 入庫
- Warehouse → Inventory にドロップ: 出庫
- デフォルト: “スタック全量”を移動
- 分割移動（推奨）
  - Shift+ドラッグ: 数量入力モーダルを出す（1〜所持数）
  - Ctrl+ドラッグ: 1個だけ
- 失敗条件（例）
  - 容量不足: 受け側に空きがない
  - 手数料不足: 所持金が足りない
  - 禁止品目: food/drink 等
  → いずれもモーダルで理由を表示し、移動は行わない

9.4 表示（アイテム行）
- 1行に以下を表示
  - 商品名
  - 数量
  - 容量（carry_size * qty）
  - カテゴリ（小さく）
- ソート: デフォルトはカテゴリ→名前、切替で数量/容量

9.5 キーボード/非D&D操作（保険）
- D&Dが不向きな環境向けに、選択→「入庫」「出庫」ボタンも併設してよい
  - ただし最終的には D&D を主操作にする

10) データ（保存形式の方針）
10.1 倉庫インベントリ
- 1拠点につき Dictionary（product_id -> qty）
- プレイヤー側に保持（他者共有の“公共在庫”にしない）

推奨キー
- warehouses: Dictionary
  - key: city_id
  - value: { "cargo": { pid: qty, ... }, "debt": float, "kind": "guild" }

10.2 利用権
- warehouse_permits_by_province: Dictionary
  - key: province（文字列）
  - value: true/false

10.3 手数料・容量
- MVPは固定値（定数）でOK
- 将来、CSVで拠点ごとに設定したくなったら warehouses.csv を追加

11) 体験版での導入ステップ（実装順の提案）
- Step1: ギルド倉庫（1州1拠点）＋利用権（Piltonのみ初期解禁）＋入出庫（ボタン操作でも可）
- Step2: 他州の利用権（rep閾値）
- Step3: 保管料（日次）
- Step4: 倉庫専用ウィンドウをD&D対応（分割移動・容量バー）
- Step5: 商館倉庫（支店）と設備アップグレード

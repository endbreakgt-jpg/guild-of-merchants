適用方法
--------
1. プロジェクトのバックアップを作成します。
2. ZIP内の gom_contract_debug_actionlog_patch_2026-07-15.txt を
   プロジェクトルートへ置きます。
3. VS Code のターミナルで次を実行します。

   git apply --check gom_contract_debug_actionlog_patch_2026-07-15.txt
   git apply gom_contract_debug_actionlog_patch_2026-07-15.txt

4. Godot 4.3 でプロジェクトを起動します。

修正内容
--------
1. 契約ウィンドウ
   - 受注済み一覧を隠してから、新規受注一覧を次フレームで開きます。
   - 新規受注一覧を閉じると、受注済み一覧へ戻ります。
   - 契約詳細ダイアログは新規受注一覧の子ウィンドウとして開きます。
   - 同じ親に排他ウィンドウが重なるエラー2件を防止します。

2. DBGパネル
   - 背景を完全不透明にします。
   - DBGボタンは実際の表示状態を基準に開閉します。
   - 2回目の押下で確実に非表示になります。

3. 行動ログ
   - 既存の world.event_log を継続利用します。
   - 保持数を50件から200件へ増やします。
   - ゲーム内日付、Day、ターンを各記録に付けます。
   - Worldのシステムメッセージ、ダイス結果、1日待機、指定日待機を記録します。
   - セーブデータからのログ復元を追加します。
   - EXPボタンで action_log_*.txt も出力します。

テストA：起動と構文
------------------
A-1. Godot起動時にスクリプト解析エラーがない。
A-2. 都市画面まで通常どおり進める。
A-3. Output / Debugger に今回変更箇所由来の新規エラーがない。

テストB：契約ウィンドウの排他制御
----------------------------------
B-1. 都市画面で「依頼（契約）」を押し、受注済み一覧を開く。
B-2. 「新規受注」を押し、新規受注一覧が開く。
B-3. この時点で次のエラーが出ない。
     - parent window already has another exclusive child
B-4. 新規受注一覧の「閉じる」を押す。
B-5. 受注済み一覧へ戻り、内容が更新されている。
B-6. B-2からB-5を3回繰り返してもエラーが出ない。
B-7. 新規受注一覧で任意の契約の「詳細」を押す。
B-8. 契約詳細が開き、排他ウィンドウのエラーが出ない。
B-9. 「キャンセル」で詳細だけが閉じ、新規受注一覧へ戻る。
B-10. 再度詳細を開いて受注する。
B-11. 新規受注一覧と受注済み一覧の内容が更新される。
B-12. ウィンドウ右上のXでも、新規受注一覧から受注済み一覧へ戻る。

テストC：DBGパネル
-----------------
C-1. DBGボタンを1回押すとパネルが表示される。
C-2. 背後の都市画面が透けず、背景が完全不透明である。
C-3. DBGボタンをもう1回押すとパネルが非表示になる。
C-4. さらに押すと再表示できる。
C-5. F3操作を使っている場合も、表示／非表示が1回ずつ切り替わる。

テストD：行動ログの記録
----------------------
D-1. 「1日待機する」を実行する。
D-2. 都市画面のメッセージ欄に次の形式の記録が出る。
     [ゲーム内日付 / Day n / Tn/n] 1日待機: Day n → Day n
D-3. 「指定日まで待機」を実行し、完了記録が出る。
D-4. 契約受注など、システムメッセージを伴う行動を行う。
D-5. その結果が日時付きでメッセージ欄へ追加される。
D-6. 同じ道中イベントが二重記録されない。

テストE：EXPによる共有ファイル出力
---------------------------------
E-1. 上部のEXPボタンを押す。
E-2. 出力通知に次の3ファイルが表示される。
     - action_log_day....txt
     - eco_report_day....txt
     - eco_day....csv
E-3. 通知内容がクリップボードへコピーされる。
E-4. action_log_*.txt を開き、次が含まれることを確認する。
     - 出力日時
     - ゲーム内日時
     - 現在地
     - 所持金
     - 積載量
     - 総合信用
     - 古い順の行動記録
E-5. 出力先は従来と同じ user://exports である。

テストF：セーブ／ロード
----------------------
F-1. 行動を数件行った後にセーブする。
F-2. さらに別の行動を行う。
F-3. F-1のセーブをロードする。
F-4. セーブ時点までの行動ログが復元される。
F-5. ロード後のEXP出力にも復元されたログが含まれる。

報告時に共有いただきたいもの
----------------------------
1. action_log_*.txt
2. Godot Debuggerのエラー全文（発生した場合）
3. どのテスト番号で発生したか
4. 直前に押したボタン
